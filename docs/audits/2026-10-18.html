PRODUCT & RELIABILITY REVIEW

A strong preview.
Make saving and recovery safer next.

18 October 2026 · Review baseline: BailaCue 0.2.5 / build8.

Source and UX review, prior native screenshots, current unit/browser checks and synthetic failure reproductions; no production database writes or private user media access.

First priorities

  1. Protect device-only clips and metadata during restore
  2. Make logout and cleanup failure-safe
  3. Make confirmed online saves durable before deleting the phone file
  4. Then simplify player/onboarding and scale large libraries

The requested rating-led Salsa/Bachata daily mix is implemented in the new source. Other findings remain recommendations; no broad fixes or production changes were silently applied.

BailaCue or BailaQue?

The owner chose to keep BailaCue. Cue expresses a practice prompt in English. Que is generally read keh in Spanish and may need pronunciation/spelling reinforcement. This is a naming recommendation, not a trademark or store-availability search.

A display-name change can preserve the installed package, signing certificate, OAuth registration and existing local data; do not rename internal identifiers merely for branding.

High · Sync · A01

Cloud restore can hide local-only clips

Restoring an older cloud snapshot replaces the entire video list. A local-only clip absent from that snapshot disappears from the library even though its phone file remains. No merge preview or undo is offered.

Improve: Keep local-only entries or archive them, show a restore preview and create a recoverable local backup before replacing metadata.

Reproduced with the real restoreSnapshot function and synthetic metadata: one local entry became zero.

High · Accounts · A02

A cleanup failure can prevent sign-out

Sign-out is reached only after reminders, file deletions, provider disconnects and library removal. A filesystem/provider error aborts cleanup before clearing the app session.

Improve: Make session teardown unconditional, track cleanup failures separately and retry leftover file removal. Explicitly identify unsynced/local-only material before destructive account cleanup.

Injected a filesystem failure into the actual cleanup function; account.logout was never reached. No real account or file was deleted.

High · Uploads · A03

Online-only cleanup runs before durable metadata commit

The provider has the completed video, but React state updates are persisted later through a queued effect. A force-stop or storage write failure after local file deletion can leave stale local references or lose recent metadata. This does not mean the confirmed cloud MP4 is deleted.

Improve: Persist a confirmed-upload receipt and the new library entry before removing the local file. Make cleanup a recoverable transaction with a journal.

Ordering confirmed in source. The force-stop/storage-failure scenario has not been reproduced on a physical phone.

Medium · Sync · A04

Snapshots lack structural runtime validation

Server validation checks object size and forbidden keys, but an incomplete/version-incompatible object can be saved. Restore assumes arrays exist and can throw.

Improve: Validate snapshots against a versioned runtime schema on both sides; reject malformed payloads before changing the device library and retain a last-known-good copy.

The real restoreSnapshot({version:1}, local) threw a missing-map error. Production was not queried or modified.

Medium · Offline storage · A05

Expired authentication is treated like revoked file permission

Provider reauth errors enter the same download-deletion path as missing/restricted files. A temporary login problem can remove a useful offline download.

Improve: Distinguish expired sign-in from confirmed permission revocation. Request reconnect without deleting the file solely because of token expiry; keep explicit provider restriction handling.

Medium · Performance · A06

Large libraries render every card and scans repeatedly search arrays

The library uses ScrollView with map, and reconciliation repeatedly uses findIndex. Work grows with the full library rather than visible items.

Improve: Use a virtualized list, indexed maps for provider identities, memoized search and bounded thumbnail caches. Benchmark 100, 1000 and 10000 videos before setting performance claims.

Medium · Onboarding · A08

Provider registration and reconnect flows need a simpler user journey

The app still requires one-time app-level OAuth registration and users can encounter app-key/setup terminology. Multiple Google connections also require careful account switching: token lookup explicitly refuses the wrong current Google user.

Improve: Finish app-owner registration, guide users through connect, select Salsa/Bachata folders and upload permission in one flow, and show the account identity on every reconnect. Test real consent and expiry with both folders.

Source review and existing mocked tests only; real Google/Dropbox transfers remain unverified here.
